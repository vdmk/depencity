# Graph model cases

- **Operations and assignments:** In `total = left + right; total = total * 2`, each operation depends on its input values, and each assignment creates a value version read by the next operation. ([py](cases-examples/operations-and-assignments.py), [graph](cases-examples/operations-and-assignments.svg))
- **Function calls:** A resolved call depends on its arguments and on the called function's result; the function body connects its parameter to that result. ([py](cases-examples/function-calls.py), [graph](cases-examples/function-calls.svg))
- **Multiple function arguments:** In `combine(left, right, scale=factor)`, all three argument values feed the call. Inside `combine(first, second, scale)`, the parameters feed its operations and return. No edges map `left` to `first`, `right` to `second`, or `factor` to `scale`; the call also depends on the function's return. ([py](cases-examples/multiple-function-arguments.py), [graph](cases-examples/multiple-function-arguments.svg))
- **Function outputs:** Explicit returns, yielded values, values received when a generator resumes from `yield`, and implicit `None` completion are distinct. ([py](cases-examples/function-outputs.py), [graph](cases-examples/function-outputs.svg))
- **Short-circuit expressions:** In `flag and compute(value)`, `flag` governs whether the call runs and contributes to the result; it does not determine the call's result. ([py](cases-examples/short-circuit.py), [graph](cases-examples/short-circuit.svg))
- **Class method calls:** Constructing a known class and calling one of its methods connects the constructor and method outputs to their call nodes, along with the explicit argument. ([py](cases-examples/class-members.py), [graph](cases-examples/class-members.svg))
- **Member and subscript writes:** An attribute write depends on its receiver and assigned value; a subscript write also depends on its index. The graph records the write access without inferring mutations through aliases. ([py](cases-examples/member-writes.py), [graph](cases-examples/member-writes.svg))
- **Writes through function arguments:** A member or subscript write inside a function depends on the receiver argument and assigned values (including the index for a subscript). The graph records the write in the function scope; it does not propagate the mutation back through aliases at the call site. ([py](cases-examples/function-argument-writes.py), [graph](cases-examples/function-argument-writes.svg))
- **Exception handling:** Handler conditions follow the `try` body and depend on its computed values and the exception types. Multiple handlers form a chain of conditions. These conditions govern assignments from the body and handlers; a bound exception value flows into its handler's assignment. ([py](cases-examples/exception-handling.py), [graph](cases-examples/exception-handling.svg))
- **Comprehension iteration:** In `[1 for i in items if flag]`, the iterable governs whether and how often the filter and result contribute. The dependency edge expresses this gating relation; it does not mean the iterable determines the filter's boolean value. ([py](cases-examples/comprehension-iteration.py), [graph](cases-examples/comprehension-iteration.svg))
- **For loops:** In `for i in items: if flag: yield 1`, the iterable governs whether the inner condition and yield contribute, matching comprehension iteration. ([py](cases-examples/for-loop.py), [graph](cases-examples/for-loop.svg))
- **While loops:** In `while condition: yield value`, the condition governs whether the body and yielded value contribute on each iteration. ([py](cases-examples/while-loop.py), [graph](cases-examples/while-loop.svg))
- **Conditional assignments:** In `if val: a = b; c = d; f = b + d`, the branch condition governs each value written in the branch. The resulting values depend on the condition, assigned inputs, and prior values retained when the condition is false; source input values remain independent of the condition. ([py](cases-examples/conditional-assignments.py), [graph](cases-examples/conditional-assignments.svg))
- **Class-body global writes:** A `global` write in a class body remains a source operation owned by the class scope, with the module as its binding owner. The model does not propagate that write to reads or exports in other scopes: in this example, `main` reads the earlier module-level `published` value. ([py](cases-examples/class-body-global-writes.py), [graph](cases-examples/class-body-global-writes.svg))
